# Stable Observation Cycle

## 为什么现在进入冻结期

当前系统已经具备：
- 主分层
- 观察层
- 候选池质量看板
- 研究与审计护栏

下一步最重要的，不再是继续加因子、加标签、加执行规则，而是验证这套三层结构在连续样本外周期里是否真的稳定、可信、能持续提升候选池理解和选股质量。

## 冻结期允许做什么

- 修 bug
- 补运行监控
- 补候选池质量看板
- 补日志、报告结构、复盘输出
- 观察主策略 top20 / top10 / top5 的质量变化
- 观察观察层标签是否真的帮助理解候选池

## 冻结期不允许做什么

- 不新增主分因子
- 不调整主分权重
- 不把观察层标签抬进主分
- 不默认启用新的融合版本
- 不新增执行管理规则
- 不把观察层标签自动升级成执行规则
- 不再新增新的观察层标签

## 每天看什么

1. `08:58` 晨报：主策略、低价弹性、短线机会的盘前重点。
2. `20:00` 三合一晚报：主策略、低价弹性、短线机会与风控同日结果。
3. `20:20` 稳定观察检测：自动生成候选池质量看板，检查 top20 / top10 / top5 的收益、命中率、回撤、胜率、盈亏比。
4. 观察层：
   - 龙头扩散
   - 兑现压力
5. 失败归因：
   - 是排序错了
   - 还是兑现路径错了

## 每周看什么

1. 周五 `21:00` 观察期周检是否仍然给出 `keep_frozen = true`。
2. 候选池质量是在改善、持平，还是恶化。
3. 观察标签分组里：
   - 哪些更像“会冲一下”
   - 哪些更接近“可兑现收益”
4. 当前是否存在足够清晰的新证据，足以打破冻结状态。

如果没有，就明确保持：
- `keep_frozen = true`

## 什么时候才允许重新进入开发 / 升级期

只有当以下条件至少有一条成立，才允许讨论解冻：

1. 候选池质量在跨时间窗口里出现稳定改善。
2. 观察层信息显示出动作含义清楚、且跨时间稳定的模式。
3. 新研究问题不仅增加信息维度，而且明确改善候选池质量或动作清晰度。

如果做不到这三条中的任何一条，就继续停留在：
- 低改动运行
- 高质量复盘
- 保持冻结
