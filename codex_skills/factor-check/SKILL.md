# factor-check

只做一件事：新因子先体检，再入库。

## 什么时候用

- 用户新增了一个 alpha
- 用户怀疑一个因子只是重复动量
- 用户要判断某因子应不应该并入主分

## 先看什么

1. 因子实现文件
2. 对应标签 horizon
3. `references/checklist.md`
4. 现有实验脚本：
   - `scripts/run_ablation_suite.py`
   - `scripts/run_walk_forward_grid.py`
   - `scripts/run_candidate_rerank_validation.py`

## 必查项

1. 时间对齐是否安全
2. 缺失率是否过高
3. 极值是否失控
4. 和现有主因子是否高度重复
5. 前 5% / 10% / 20% 分层命中率是否高于底盘
6. 接入主系统后有没有净增量

## 检查顺序

1. 看因子定义和经济含义
2. 查未来函数风险
3. 跑单因子分层
4. 跑候选池重排或小权重融合
5. 只要系统级没增量，就不要入主分

## 输出要求

必须给出表格：

| 检查项 | 结果 | 结论 |
| --- | --- | --- |

再给：

| 决策 | 含义 |
| --- | --- |
| 入库 | 可以进主分 |
| 观察 | 只做辅助标签 |
| 放弃 | 不值得继续 |
